# Huihui Qwen3.8 A100 40GB vision round trips — 2026-10-03

All three configurations were tested with real image inputs through the app’s metering proxy and SSH tunnel on NVIDIA A100-SXM4-40GB runtimes. 27B GGUF and EXL3 shared one VM; Flash-Next ran on a fresh VM after an engine-switching bug was fixed. Native engine capability probes reported vision enabled. This extends the [earlier text benchmark](2026-10-03-huihui-a10040.md), which sent no images: its 27B projector was loaded, and Flash-Next had vision disabled.

The runtime exposed 40,960 MiB VRAM and 89.6 GB system RAM. Tests used 8,192-token context, one slot, temperature 0, seed 42, reasoning disabled, and f16 KV for llama.cpp / FP16 KV for EXL3. These measurements do not validate the larger context defaults of the existing 27B presets.

## Performance

Each cell is a median of three streamed requests, each producing 128 output tokens. Generation speed uses engine-reported generation time. TTFT and end-to-end speed include the client, proxy, SSH tunnel and any prefill/image encoding performed. Warm-up and acceptance requests are excluded. Image benchmarks reuse image A after the acceptance checks: this is a warm repeated-image workload, and engine caching may affect latency. It is not a cold image-encoding benchmark; acceptance-request timings are also retained in the JSON.

## Vision acceptance

The same two 768×384 PNG fixtures and prompts were used for every configuration. Image A contains a red circle, blue square and green triangle; image B contains a mustard-yellow triangle and purple circle. Checks cover each image with an identical JSON-description prompt, a follow-up retaining image history, two-image counting, streamed image counting, and a text request after image streaming. All requests must complete successfully; answer grading remains separate from transport and throughput.

| Configuration | Exact-answer checks | Vision placement | Loaded VRAM MiB |
|---|---:|---|---:|
| 27B GGUF Q4_K | 5/6 | GPU projector | 17,502 |
| 27B EXL3 4.0 bpw | 6/6 | System RAM, streamed to GPU for encoding | 14,552 |
| Flash-Next GGUF UD-Q4_K_XL | 6/6 | CPU projector | 39,078 |

Loaded VRAM is the reading after setup, not a peak during image encoding. Flash-Next’s 111.33 GB weight set requires CPU offload on this GPU; its projector stays on CPU. EXL3 uses its bundled vision component with `vision = true` and `vision_offload = true`.

Exact-answer mismatches are preserved below and in the JSON evidence. A yellow/orange color disagreement on image B is not evidence that the image was ignored.
